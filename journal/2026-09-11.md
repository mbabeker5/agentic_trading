# Journal 2026-09-11 (Friday, fourth trading day, all five books dry run)

A fourth zero, and the first one where the machinery was not the problem. Every
scheduled job fired, the Mac stayed awake all day, the Gateway was repaired
twice without anybody looking, and 48 of 49 alerts got through. All five books
still finished flat at 100,000.00 on 100,000.00, with no positions, no orders
and no model called.

What today bought is not a result, it is a clear view. With the machine finally
out of the way, four separate reasons the books cannot trade became visible at
once, and one of them is the first fault in this run that would have cost real
money rather than just a day.

Two lines matter more than the rest of this entry.

**The check that is supposed to prove the prices are current cannot tell a
current price from a fifteen minute old one, and it said "real time quote" twice
today about prices that were provably delayed.** Details in "What broke", item
10. This is the first fault in four days that would have taken money rather than
a day.

**And the reason the 9 AM check fails every morning is now known, after three
days of not knowing.** One line of launchd configuration kills the MCP server at
the end of every tick, so the pre-flight looks for it in the gap between ticks
and finds nothing. Details in "What broke", item 3. It is a one word fix and it
unblocks the whole day.

**3. The reconcile failure was not about the books and the broker disagreeing at

previous MCP server died at 07:30:13. The pre-flight ran at 09:00:05 and got
connection refused. The 09:00 tick started its own copy at 09:00:05, which was
answering from 09:00:07 to 09:00:11, and that tick read the account fine
("worth 1,000,690.40") and logged "Reconciliation: everything matched". **The
pre-flight missed a working MCP server by about two seconds.** So: launchd kills
the server at the end of each tick, so the pre-flight finds nothing listening,
so the verdict is fail, so `NO_TRADE_TODAY` is written, so no book trades, on
any day. Item 27 is filed as "the smallest item here". It is the item that

**The machine is no longer the biggest risk, for the first time in the run.**
All 110 scheduled wake-ups fired. 77 of 79 market ticks completed. 48 of 49
alerts reached Slack. The recorder ran all 81 of its slots. For comparison across the four trading
days, market ticks completed were 75, 43, 46 and today 77, and alerts that lost
the Slack leg were 6, 20, 19 and today 1. Yesterday's conclusion was that the
machine and the login had become bigger risks than anything in the code. Both
were addressed last night and both behaved today, which promotes the code to the
front of the queue.

**Three parts of this project read the same quote feed three different ways, and
only one of them is right.** The recorder asks for live, is refused, falls back
to delayed and records what it got, with the warning "Gateway will not serve
live quotes on this account, so the rest of the run asks for delayed data
instead" on 78 of its 81 slots, and **every one of the 188 snapshots it took
carries a price**. The trading loop asks for live, gets nothing, has no fallback,
and halts. The watchdog asks for live, sometimes gets a delayed price with no
error code attached, and reports it as real time. Same Gateway, same account,
same minutes.

**The MCP server dying between ticks is what cancels every trading day, and
launchd is doing the killing on purpose.** `AbandonProcessGroup` is `false` in
the tick job, so macOS tears down the whole process group when `run_tick.sh`
exits, including the server that script started in the background and
deliberately never stops. `run_tick.sh` and the plist have opposite intentions
and the plist wins. Backlog item 27 has been open since 2026-09-09 with "nothing
in the repository explains why"; now something does, and the item moves from the
bottom of the list to near the top, because the thing it causes is the 09:00
pre-flight failing every morning.

**Book C has two independent bugs, not one, and either alone is fatal to it.**
The known one, backlog item 31, is that
`/Users/mtalib/workspace_repos/personal_repo/agentic_trading/agent/loop.py` line
1209 builds the shortlist file name from the day the sweep runs, so the 16:30
sweep overwrites the file the 09:45 pick already read that morning. The new one
is in
`/Users/mtalib/workspace_repos/personal_repo/agentic_trading/agent/sweep_insider.py`
lines 1285 to 1287: the cutoff for which filings to read defaults to **midnight
Eastern this morning**, and nothing passes anything else. Form 4 filings are
accepted mostly in the afternoon, and today's eight were accepted between 14:13

The strategy file at
`/Users/mtalib/workspace_repos/personal_repo/agentic_trading/strategies/insider/strategy.yaml`
line 83 says the morning sweep should "parse everything accepted since last

**Books C and D cannot produce a pick at all while every book is in dry run, and

## Proposals for Mo

**1. Make the market data check read what arrived, not what was asked for.** One
change at
`/Users/mtalib/workspace_repos/personal_repo/agentic_trading/agent/watchdog.py`
line 1373: before passing, read `ticker.marketDataType` and require it to be 1.
If it is 3, fail with "delayed", which is true, instead of passing with "real
time quote", which is false. This is the only fault found in four days that
would have moved money, because `agent/preflight.py` line 268 calls the same
function and a pre-flight that passes on a delayed quote clears all five books to
buy on a fifteen minute old price. Cost: a few lines and one test that fakes a
type 3 reply. Risk: none in the dangerous direction. It can only ever refuse
where it used to allow.

**2. Decide whether the MCP server is a service or a child, and make the two
files agree.** This is backlog item 27, filed as the smallest thing on the list,
and today showed it is the thing that cancels every trading day and gave up its
cause. Right now `agent/run_tick.sh` starts a background server and never stops
it, which is what a long-lived service looks like, while
`config/launchd/com.mtalib.agentic-trading.tick.plist` sets
`AbandonProcessGroup` to false, which kills it the moment the tick ends. Two
choices, both small. Either set `AbandonProcessGroup` to true so the server
outlives the tick, or accept it as a per-tick child and have
`agent/preflight.py` start its own before the reconcile check. The first is one
word and restores the behaviour the project had before 2026-09-09. The second is
safer against a server that hangs on shutdown, which item 27 has already seen
once and which happened again tonight: the 16:30 server logged "Waiting for
connections to close" at 16:31:22 and never logged a finish. Whichever is
chosen, that shutdown needs a bounded wait and then a kill. Until one of them
happens, the pre-flight will fail its reconcile check every single morning and
write `NO_TRADE_TODAY` every single morning, whatever else is working.

**3. Buy the market data subscription.** Fourth day, unchanged. 187 instances of
IBKR error 10089 in the recorder's log alone today. The streaming NBBO networks
cost 4.50 dollars a month in Client Portal and then have to be shared with the
paper account. Until this happens, Book D halts every morning and the momentum
books cannot be judged even on a day when everything else works. Cost: 4.50
dollars a month and ten minutes. Risk: none. It is the cheapest item on this
list and the oldest.

**4. Give the loop the recorder's fallback, without loosening the rule about
opening positions.** Today the recorder got a price for every symbol it asked
about and the loop got nothing, purely because the recorder re-asks for delayed
data when live is refused and the loop does not. Keep the existing rule exactly
as it is, only a live quote lets a book open something, but ask again for delayed
so the price floor and the liquidity floor can at least be measured and recorded.
Book D would still not have traded today; it would have produced a shortlist
funnel we could read instead of fifteen identical "no price came back" notes.
Cost: small, and the pattern already exists in
`/Users/mtalib/workspace_repos/personal_repo/agentic_trading/agent/replay/record_day.py`
to copy from. Risk: none to safety, because the entry rule does not move.

**5. Fix both of Book C's bugs at once, or neither.** The 16:30 sweep writes
`insider_shortlist_<tomorrow>.json`, and the 07:00 sweep is given a `--since` of
the last sweep time rather than midnight. The loop already records the last sweep
time in `state.swept_at`, it simply never passes it. Doing one without the other
leaves the book dead in a different way. Cost: two small changes and two tests.
Risk: a shortlist built before yesterday's close is a few hours old by the next
morning's pick, which is the design the strategy file already describes.

**6. Decide what books C and D are for while everything is in dry run.** As
written they cannot pick anything, ever, because dry run means no model and the
rules only fallback only understands opening range breakouts. Three honest
options: let those two books call their model even in dry run, since a model call
places no order and costs cents; or write a rules only path for filing driven
books; or accept that C and D are parked and stop reading their daily zero as a
result. Doing nothing is the only bad option, because right now they produce a
clean looking 0.00 every day that means nothing at all. This one is a decision
rather than a fix, which is why it is yours.

**7. Fix both halves of the restart confirmation.** Two separate small changes to
the same check. Widen the 30 second window, because the 11:26 restart met three
of four tests immediately and the fourth three minutes later and was written down
as a failure; either wait longer or report "restarted, still waiting on IBKR" as
its own outcome. And make the "newer login" test ignore the line `Login has
completed: exiting via [File, Close] menu`, which is IBC logging a shutdown and
which currently makes that test pass for free every time the watchdog stops a
Gateway. Cost: a constant and a string match, plus two tests. Risk: a genuinely
failed restart is called successful for a few minutes longer, which the next
watchdog run five minutes later catches anyway. The second half has no downside
at all; it is a safety check that is currently measuring nothing.

**7a. Make the recorder count an empty slot as a miss.** Today's manifest says
`slots_missed []` and "Recorded cleanly. This day is ready to replay" about a day
with no prices at all between 11:15 and 11:25. It counts slots that ran, not
slots that produced data. Cost: one condition and one test. Risk: none, and the
alternative is replaying a day against a silent hole and trusting the answer.

**8. Click the paper trading disclaimer in the Gateway window.** Error 10141 is
now dated to today, and it sits in the same block as the failed reconnect at
